Guía de Integración y Documentación de la API (v1)

Autenticación y Cabeceras Cómo enviar credenciales en llamadas programáticas

Para consumir los endpoints de la API, debe enviar su clave de API generada a través de alguna de las siguientes cabeceras HTTP:

  • X-API-KEY: bsoc_key_tu_token_aqui
  • Authorization: Bearer bsoc_key_tu_token_aqui
📌 Cómo armar la URL del servidor (Base URL):

Los ejemplos del manual usan rutas relativas (ej: /api/v1/users). En Postman, scripts o SOAR, debe anteponer la IP o dominio del servidor del Backend:

  • Local (Desarrollo): http://localhost:3000/api/v1/users
  • Servidor (Producción): https://IP_DEL_SERVIDOR/api/v1/users o https://dominio-bitacora.com/api/v1/users

Ejemplo básico de consulta completa en cURL:

curl -X GET http://localhost:3000/api/v1/users \
  -H "X-API-KEY: bsoc_key_tu_token_aqui"
 Renderizar Plantilla de Correo (templates:render) Ideal para integrar el motor de plantillas de la Bitácora con un SOAR externo

El endpoint POST /api/v1/templates/render procesa la información de un incidente y retorna el código HTML final optimizado e inyectado con la plantilla correspondiente.

Detalle del JSON Payload (Cuerpo del Mensaje):

Campo Tipo Obligatorio Descripción
to Array de strings Sí Lista de correos autorizados del SOC que recibirán el reporte final.
subject String No Asunto personalizado para el correo.
paletteKey String No Color de plantilla. Opciones: cdc-verde, noche-azul, slate-pro, carbon, indigo, bosque.
reportData Object Sí Contenedor de datos del reporte. Campos internos admitidos:
  • logSource (String, Requerido): Nombre de la plataforma, cliente o fuente de logs (ej: "Sentinel_SOC").
  • criticidad (String, Requerido): Nivel de criticidad (critica, alta, media, baja, informativa).
  • ofensa (String): Número de alerta o ID de ofensa.
  • tipoOperacion (String): Ej. "Fuerza Bruta / Ransomware".
  • nombreEvento (String): Nombre descriptivo de la alerta.
  • motivoEvento (String): Breve resumen del porqué se disparó la regla.
  • origenConexion (String): Dirección IP/Hostname del host atacante.
  • destino (String): Dirección IP/Hostname del host comprometido.
  • reputacionOrigen (String): Estado de reputación del origen.
  • observaciones (String): Notas detalladas agregadas por la automatización o analista.
  • recomendacion (String): Instrucciones de respuesta y mitigación.
  • evidenciaTexto (String): Logs o fragmentos de evidencias en texto.
images Array de objetos No Lista de capturas de evidencia a embeber dentro de la plantilla. Estructura:
  • name (String): Nombre del archivo de imagen (ej: "log_screen.png").
  • contentType (String): Tipo MIME de la imagen (ej: "image/png").
  • contentBase64 (String): Datos Base64 puros sin encabezado dataURI.
sendEmail Boolean No Si es true, envía el correo de inmediato a la lista to usando el servidor SMTP configurado. (Por defecto: false).

Ejemplo de Petición cURL:

curl -X POST http://localhost:3000/api/v1/templates/render \
  -H "X-API-KEY: bsoc_key_tu_token_aqui" \
  -H "Content-Type: application/json" \
  -d '{{ '{' }}
    "to": ["destinatario@dominio-soc.com"],
    "sendEmail": true,
    "reportData": {{ '{' }}
      "logSource": "Firewall Principal",
      "criticidad": "alta",
      "ofensa": "99827",
      "nombreEvento": "Tráfico C2 Detectado",
      "origenConexion": "198.51.100.12",
      "destino": "10.0.4.150",
      "observaciones": "Se detectó tráfico recurrente hacia IPs reportadas de C2 CobaltStrike.",
      "recomendacion": "Aislar la máquina 10.0.4.150 de la red corporativa."
    {{ '}' }}
  {{ '}' }}'

Respuesta Exitosa (HTTP 200):

{{ '{' }}
  "success": true,
  "emailSent": true,
  "emailError": null,
  "subject": "Reporte de Incidente de Seguridad",
  "html": "<!doctype html><html>...</html>",
  "text": "Información del Evento...\nOfensa: 99827..."
{{ '}' }}
 Registrar Entrada en Bitácora (events:write) Crear un evento o log de forma programática en la bitácora operativa

Para registrar eventos en la bitácora del turno actual, realice una petición POST /api/v1/events con la siguiente estructura:

curl -X POST /api/v1/events \
  -H "X-API-KEY: bsoc_key_tu_token_aqui" \
  -H "Content-Type: application/json" \
  -d '{{ '{' }}
    "content": "Alerta automática: Caída de enlace principal ISP en DataCenter",
    "entryType": "operativa",
    "tags": ["Incidente", "Infraestructura"],
    "clientName": "SOC Global"
  {{ '}' }}'
 🛠️ Guía de Inicio Rápido con Postman (Paso a Paso) Guía didáctica para configurar y probar los endpoints manualmente

Sigue estos pasos precisos en Postman para evitar los errores comunes de configuración:

  1. Configurar la Petición y la URL:
    • Cambia el tipo de petición a POST.
    • Pega la URL limpia: http://localhost:3000/api/v1/templates/render.
    • ⚠️ Nota: No pongas signos de igual "=" ni llaves en la barra de direcciones de la URL.
  2. Configurar Autenticación (API Key):
    • Ve a la pestaña Authorization (abajo de la URL).
    • En Type, selecciona Bearer Token.
    • En Token, pega tu API Key completa (comienza con bsoc_key_...).
  3. Configurar el Payload (Cuerpo):
    • Ve a la pestaña Body.
    • Selecciona la opción raw.
    • En el selector desplegable de la derecha (donde dice Text), cámbialo a JSON.
    • Pega tu JSON sin comentarios de línea: 
      {{ '{' }}
  "to": ["tu-correo@netics.cl"],
  "sendEmail": true,
  "reportData": {{ '{' }}
    "logSource": "Firewall Principal",
    "criticidad": "alta",
    "nombreEvento": "Detección de malware"
  {{ '}' }}
{{ '}' }}
  4. Verificar Params (Vacío):
    • Asegúrate de que la pestaña Params esté completamente limpia.
  5. Enviar:
    • Presiona el botón azul Send. Verás un código de estado 200 OK y recibirás el correo electrónico.
